# PeF 中处理固定模块的方法总结

## 1. 问题背景

原论文《PeF: Poisson’s Equation Based Large-Scale Fixed-Outline Floorplanning》默认所有模块都可以参与全局平面规划与合法化。但在实际问题里，经常会遇到一部分模块位置已经固定的情况，例如：

- 预放置的大宏块
- 已知位置的 IP
- 必须贴近边界或指定区域的模块

这类模块不能再被移动，但仍然会：

- 占据面积
- 挡住可用空间
- 影响连线长度
- 影响其余模块的相对位置关系

因此，它们需要被视为 **fixed modules** 或 **obstacles**。

---

## 2. 总体思路

处理固定模块时，可以把模块集合拆成两部分：

- `V_fix`：固定模块
- `V_mov`：可移动模块

整体原则是：

1. 固定模块参与密度计算、势场计算和线长计算；
2. 固定模块的位置不作为优化变量；
3. 可移动模块在全局平面规划阶段绕开固定模块；
4. 合法化阶段把固定模块当作障碍物处理。

一句话概括：

**固定模块参与“影响别人”，但不参与“更新自己”。**

---

## 3. 对 PeF 数学模型的修改

### 3.1 原始 PeF 思路

PeF 的核心是：

1. 根据当前模块分布计算密度 `rho(x, y)`；
2. 解泊松方程得到电势 `psi(x, y)`；
3. 由电势求电场；
4. 用电场把模块从拥挤处推向空旷处；
5. 同时结合线长目标优化位置和软模块宽度。

原始情况下，所有模块的中心坐标 `(x_i, y_i)` 都是变量。

### 3.2 引入固定模块后的变化

如果模块 `i` 是固定模块，则：

```text
x_i = x_i*
y_i = y_i*
```

其中 `x_i*`、`y_i*` 是预先给定的固定坐标。

因此，处理方式变成：

- 对所有模块 `V_fix ∪ V_mov` 计算密度；
- 对所有模块 `V_fix ∪ V_mov` 计算线长；
- 但只对 `V_mov` 求位置梯度并更新；
- 若固定模块宽高也固定，则它们也不参与宽度优化。

于是，固定模块在数学上可以看成：

- 在密度函数中是普通模块；
- 在目标函数中提供常量位置贡献；
- 在优化变量中被移除。

这意味着 PeF 的全局平面规划主线仍然成立，不需要推翻原模型。

---

## 4. 全局平面规划阶段如何处理固定模块

### 4.1 密度与泊松势场

固定模块仍然参与密度栅格的填充。原因是：

- 它们真实占据芯片面积；
- 如果不放进密度图，其它模块会被错误地推入这些区域；
- 只有把它们放入密度分布，泊松势场才会把周围模块自然排斥出去。

因此，在密度计算时：

```text
rho(x, y) = rho_fix(x, y) + rho_mov(x, y)
```

这里：

- `rho_fix` 是固定模块贡献的密度；
- `rho_mov` 是可移动模块贡献的密度。

### 4.2 电场更新

解出势场后，固定模块和可移动模块理论上都处在电场中，但实际更新时只更新可移动模块：

```text
x_i <- x_i + delta_x_i
y_i <- y_i + delta_y_i,    for i in V_mov
```

而固定模块始终保持：

```text
x_i = x_i*
y_i = y_i*,                for i in V_fix
```

### 4.3 线长梯度

固定模块仍参与 HPWL / LSE 线长的计算，因为它们的引脚位置依然影响网络跨度。

但在梯度更新里：

- 固定模块的梯度可以计算；
- 最终更新时直接把它们的位移置零。

工程上更直接的做法是：

```text
grad_x[i] = 0
grad_y[i] = 0,   if i in V_fix
```

这样优化器只移动可移动模块。

### 4.4 软模块宽度优化

若某个模块既是软模块又是固定模块，需要进一步区分：

1. **位置固定、宽高也固定**
   - 不参与位置优化
   - 不参与宽度优化

2. **位置固定、但形状允许调整**
   - 位置不更新
   - 宽度 `w_i` 可继续优化

在当前原型里，为了简化实现，固定模块被统一当作硬模块处理，即宽高也固定。

---

## 5. 为什么合法化阶段必须专门改

原论文的合法化阶段假设模块之间的相对关系可以被整体调整和压缩。但如果存在固定模块：

- 固定模块不能移动；
- 某些关系不能随意翻转；
- 可移动模块不能“穿过”固定模块；
- 固定模块可能把区域切割成多个通道。

因此，合法化不能再把所有模块同等对待，而必须把固定模块当作障碍物处理。

这就引出了 **obstacle-aware HCG/VCG**。

---

## 6. obstacle-aware HCG/VCG 的含义

PeF 使用的思路可以继续保留成“水平/垂直相对次序约束”。

定义：

- `i -> j` 在 `HCG` 中表示：模块 `i` 在模块 `j` 左边；
- `i ↑ j` 在 `VCG` 中表示：模块 `i` 在模块 `j` 下边。

它们对应的几何约束分别是：

```text
x_j - x_i >= (w_i + w_j) / 2
y_j - y_i >= (h_i + h_j) / 2
```

当引入固定模块后，固定模块同样作为图中的顶点存在，只不过：

```text
x_i = x_i*
y_i = y_i*,   if i in V_fix
```

所以 obstacle-aware HCG/VCG 的本质就是：

**把固定模块也放进约束图中，但把它们当作不能移动的锚点。**

---

## 7. obstacle-aware HCG/VCG 的构造规则

### 7.1 基本输入

构图时需要知道每个模块当前的：

- 中心坐标 `(x_i, y_i)`
- 宽高 `(w_i, h_i)`
- 是否固定

对任意一对模块 `i, j`，先看它们当前的相对位置和重叠情况。

### 7.2 一般构图原则

对于任意一对矩形：

1. 如果它们在水平方向分离、但垂直方向有重叠  
   - 只能靠左右分开  
   - 加 `HCG` 边

2. 如果它们在垂直方向分离、但水平方向有重叠  
   - 只能靠上下分开  
   - 加 `VCG` 边

3. 如果两个方向都重叠  
   - 需要选择一个主分离方向  
   - 通常选择重叠量更大的方向去分开，或者选择更符合当前相对位置的方向

4. 如果两个方向都不重叠  
   - 不需要同时加两种关系  
   - 一般只加一条主导边，避免图过密

### 7.3 遇到固定模块时

如果一对模块中有一个是固定模块，一个是可移动模块：

- 若决定让可移动模块在固定块右边，则加 `fixed -> movable`
- 若决定让可移动模块在固定块左边，则加 `movable -> fixed`
- 若决定让可移动模块在固定块上方，则加对应的 `VCG` 关系
- 若决定让可移动模块在固定块下方，则加另一种 `VCG` 关系

这里的关键不是“固定块是否进图”，而是：

**它进图，但边的方向决定了可移动模块只能从哪一侧绕开它。**

---

## 8. obstacle-aware 合法化的基本流程

在原型里，合法化不是直接照搬论文原始实现，而是采用了：

**约束图引导的 packing / legalization**

流程如下：

### 8.1 构造 HCG / VCG

根据全局平面规划结果，构造：

- 水平约束图 `HCG`
- 垂直约束图 `VCG`

### 8.2 固定模块先落位

所有固定模块先被放入最终布局中，并锁定它们的位置：

```text
left_i = x_i* - w_i / 2
bottom_i = y_i* - h_i / 2
```

### 8.3 用图决定放置顺序

对 `HCG` 和 `VCG` 做拓扑排序，得到一个大致顺序。  
这个顺序用来决定：

- 哪些模块应该优先放；
- 哪些模块应当在其它模块之后放；
- 哪些模块更适合出现在右侧或上侧。

### 8.4 图引导的 bottom-left 放置

对每个可移动模块：

1. 先根据 `HCG/VCG` 计算它的推荐区域；
2. 再从一组候选位置中尝试放置；
3. 选择一个：
   - 不与已放模块重叠
   - 不与固定模块重叠
   - 尽量满足图约束
   - 尽量靠近全局平面规划结果

这种方法的特点是：

- 图约束用于“指导”；
- 实际不重叠由 packing 过程保证；
- 对原型实现更稳，不容易因为约束过密而无解。

## 9. 当前原型实现中的具体取舍

当前代码文件是：

- [pef_obstacle_repro.py](D:/EDA/论文/PeF/pef_obstacle_repro.py)

它的关键实现点如下：

### 9.1 随机生成固定模块

入口函数：

- [generate_random_instance_with_obstacles](D:/EDA/论文/PeF/pef_obstacle_repro.py:258)

做法：

- 随机选出一部分模块作为固定模块；
- 固定模块默认当作硬模块处理；
- 给固定模块分配不参与后续移动的初始位置。

### 9.2 带固定模块的全局平面规划

入口函数：

- [global_floorplan_with_obstacles](D:/EDA/论文/PeF/pef_obstacle_repro.py:380)

做法：

- 固定模块参与密度场；
- 固定模块参与线长计算；
- 固定模块的 `x/y` 更新量强制为 0；
- 只有可移动模块会被电场和线长梯度推动；
- 固定模块宽高保持不变。

### 9.3 obstacle-aware HCG/VCG 构图

入口函数：

- [build_obstacle_aware_constraint_graphs](D:/EDA/论文/PeF/pef_obstacle_repro.py:462)

做法：

- 根据当前几何关系为模块对选择水平或垂直关系；
- 固定模块也进入图；
- 对于 fixed-movable 对，优先确定“可移动模块从固定块哪一侧绕开”。

### 9.4 obstacle-aware 合法化

入口函数：

- [legalize_with_obstacle_aware_graphs](D:/EDA/论文/PeF/pef_obstacle_repro.py:654)

它内部采用：

1. 图约束求推荐位置；
2. 再做受约束的 bottom-left 打包；
3. 最终保证与固定模块和已放模块不重叠。

### 9.5 固定模块的可视化标记

绘图入口：

- [draw_floorplan](D:/EDA/论文/PeF/pef_obstacle_repro.py:878)

固定模块在图中用如下方式标记：

- 洋红/紫红色填充
- `xx` hatch
- 对角叉线
- 编号前缀 `F`

这样便于快速区分：

- 固定模块
- 可移动硬模块
- 可移动软模块

## 10. 当前方法的优点

1. **保留了 PeF 的核心主线**  
   不需要推翻 Poisson 密度驱动的全局平面规划框架。

2. **固定模块的影响被真实建模**  
   它们既参与密度，又参与线长，而不是简单忽略。

3. **合法化阶段具备 obstacle awareness**  
   可移动模块不会再被当作能随意穿过固定块。

4. **实现稳定，便于验证**  
   对原型实验和可视化演示比较合适。

---

## 11. 当前方法的局限

1. **不是论文合法化部分的逐公式复现**  
   当前实现更偏原型和工程化近似。

2. **HCG/VCG 更多是引导作用**  
   最终可行解主要靠图引导下的 packing 保证。

3. **固定块过多或空白率过低时，问题可能无可行解**  
   这不是算法错误，而是布局本身塞不下。

4. **最终 HPWL 未必优于全局阶段**  
   合法化的主要任务是去重叠和满足障碍约束，不一定继续改善线长。

---

## 12. 适合继续改进的方向

如果要继续向更接近论文、或更接近工业实现的方向走，下一步通常有三条路线：

1. **把 HCG/VCG 的删边、换边策略做得更完整**
   - 更接近原论文 legalization 的逻辑

2. **支持外部输入固定模块位置**
   - 而不是随机生成固定块

3. **加入 region / channel 约束**
   - 让模块不仅绕开障碍，还能限定在特定走廊或区域内

---

## 13. 总结

处理固定模块时，最关键的思想是：

1. 固定模块不是“忽略掉”的模块，而是 **参与势场与线长的障碍物**；
2. 全局平面规划仍然可以沿用 PeF 的泊松方程主线；
3. 真正需要重点改的是合法化阶段；
4. obstacle-aware HCG/VCG 的作用，是把固定模块纳入相对位置约束体系；
5. 最终可行解需要同时满足：
   - 固定模块不动
   - 可移动模块不重叠
   - 模块仍在固定轮廓内

所以，从方法论上说：

**PeF 可以扩展到有固定模块的场景，但必须把固定模块当成障碍物来参与全流程，而不能只在最后阶段临时处理。**
